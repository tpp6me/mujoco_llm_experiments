# C1: signed-in Codex visual controller development pilot

Declared 2026-09-13 before the first simulator episode. This is a new development
condition, separate from L2's historical exact-state API condition and the cancelled
V1 API proposal. The user confirmed that the signed-in Codex CLI should choose robot
actions. No direct API integration, API-key login or AGY execution is permitted.

## Fixed condition

- Exactly one randomized development episode: seed 820. No seeds 840–849.
- Supported G1, fixed pelvis, right hand, existing scene and guarded primitives.
- `codex-cli 0.154.0`, ChatGPT login, requested model `gpt-5.6-sol`, low reasoning.
  This records a requested model identifier; the CLI event stream does not verify
  the backend model snapshot. CLI system instructions differ from the old API run.
- Fixed RGB camera, 960 x 720 PNG, public calibration and robot proprioception.
  No estimated object pose from P1–P5, private truth, scoring or scripted grasp recipe
  enters the prompt. Use the existing `VISUAL_PROMPT` plus the adapter's decision
  instruction. A new ephemeral CLI session receives each image and up to 20 public
  action outcomes. No conversation resume or implicit memory.
- At most 20 CLI invocations/actions and simulated deadline t=25 s including reset.
  Physics pauses during decisions. Each CLI process has a 120 s wall timeout.
  The wrapper never retries a decision. CLI internal network requests are not
  measured; invocation counts must not be described as API request counts.
  No enforced output-token cap is claimed for this CLI condition.
- Tools, shell, web, apps, plugins, memory, host skill discovery and agent delegation
  are disabled through the version-pinned configuration in `codex_policy.py`.
  Ignore user config and rules; project instruction byte limit zero; temporary
  working directory contains only the public image and action schema.
- Audit the JSONL event stream before executing an action. Require exactly one
  completed turn and final command agreeing with the output file. Reject tool
  events, errors and extra messages. The sole permitted error-typed notice is the
  exact disabled-code-mode-host startup notice before the turn starts. It reports
  an intentionally unavailable tool host; arbitrary errors remain fatal.
- The CLI owns authentication discovery. The child environment forwards only
  ordinary path, locale and login-discovery variables. No API-key or endpoint
  environment variables are forwarded. Read-only sandboxing alone is not a claim
  of filesystem confidentiality: the input restriction relies on disabling tools,
  config/skill discovery, the isolated working directory and event auditing.
