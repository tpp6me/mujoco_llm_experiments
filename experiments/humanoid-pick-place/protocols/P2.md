# P2 manipulation visibility and support-prior audit

Frozen 2026-09-12 before seeds 760–779. Perception development only: the exact-state
G2 conventional policy drives every action. This is not an RGB control condition,
a carried-pose qualification, or an LLM comparison. No API calls are made.

## Development and frozen condition

Three development trajectories, seeds 740–742, supplied 36 fixed-camera images.
The initial P1 estimator rejected all 12 lift/hold/transport/lower images. It also
accepted 11 of 12 release/retract/park/settle images with about 12.5 mm 3D error:
it continued to assume table support while the block sat on the basket floor.
These examples motivate an explicit prior lifetime, not a new 3D pose estimator.

Freeze source hashes before 20 new episodes, seeds 760–779. Keep the existing RGB
camera, lighting, scene, object dimensions and G2 recipe (release Z .88 m, closure
.4). Capture at reset and after each attempted action, normally 12 frames per
completed episode. This samples action endpoints; it cannot characterize transient
occlusion or loss within a two-second action. No tuning or seed replacement.

## Information boundary and behavior

Perception consumes public RGB/camera/time/opaque observation IDs only. At episode
initialization, the known upright/table support prior permits a P1 estimate. Before
any action attempt (including rejection), expire that prior permanently for this
instance. Time advancement also expires it. Repeated IDs or time reversal are
errors; episode reset requires a new instance. Fresh images do not restore support.

After expiry, report red-pixel visibility, centroid and bounds but no 3D pose. Red
pixels are not proof of a held object, successful grasp, full visibility or placement.
No stale position is reused. The existing one-use VisualSession enforces action
freshness. All policy actions must pass through PerceptionSession; this is a local
interface contract, not process isolation from arbitrary Python access.

The evaluator's exact-state driver uses private truth to execute G2 and to measure
errors after capture; those fields never enter the perception function. Retain
private records separately from public observations/perception artifacts.

## Accounting

Retain all 20 episodes, failed actions, early stops, and every captured frame. Report
actual/expected frame counts and stage denominators, visibility detections/losses,
initial XYZ error, and whether any post-action frame exposes a supported pose.
Compare the raw P1 estimate on every image privately to document invalid-prior
acceptances. Treat 5 mm 3D error as a diagnostic development screen only.

Record red bounds against privately projected full cuboid bounds (2 px tolerance),
and visible-centroid distance from the projected true center. Neither is an
occlusion fraction or a 3D pose score. Verify exact integration-state preservation
for every capture. Report driving-policy failures separately. No visibility-rate
threshold qualifies a carried pose or a full visual controller.

A passing lifetime regression requires zero post-action supported poses, including
a synthetic loss and a rejected action. That is an interface invariant, not measured
perception accuracy. Carried 3D pose, occlusion recovery and RGB control remain open.
